## Benchmark scripts (in `docs/superpowers/benchmark/`)

No cluster URL, tenant id or credentials are stored anywhere; pass them by environment variable only.

- `BenchmarkOpenSearchSqlCluster.java.txt`: JUnit test, env-gated by `OS_SQL_URL` (skipped otherwise). Copy it to `plugin/trino-opensearch-sql/src/test/java/io/trino/plugin/opensearch/sql/BenchmarkOpenSearchSqlCluster.java` (drop the `.txt`) and do NOT commit it. Environment variables: `OS_SQL_URL`, `OS_BENCH_TENANT`, `OS_BENCH_OPTIONS=on|off`, `OS_BENCH_ONLY=<labels>` (A-L), `OS_BENCH_ROUNDS`. Labels: A count(*), B min, C max, D sum, E avg, F count with tenant, G sum with tenant, H max with tenant, I top10 with tenant, J top10, K group by workspacetype, L group by with tenant. Results go to a markdown file (see the code for the path; change it for the new laptop).
- `latency_aggregates.py`, `latency_filter_sort_groupby.py`: direct-to-SQL-plugin latency (no Trino), `python latency_aggregates.py 25`; need `OS_SQL_URL` (+ `OS_BENCH_TENANT` for the second script).

Run (from the repo root, with the sibling installed first: `./mvnw install -pl plugin/trino-opensearch -DskipTests -Dair.check.skip-all=true -nsu`; do not rebuild while a benchmark runs):

```bash
OS_SQL_URL=<cluster url> OS_BENCH_TENANT=<tenant id> OS_BENCH_ONLY=K,L ./mvnw -pl plugin/trino-opensearch-sql test -Dtest=BenchmarkOpenSearchSqlCluster -Dair.check.skip-all=true -nsu
```

The cluster is a VPC endpoint: the new laptop needs the same VPN/network access. Unpushed queries fetch ~4M rows and take 8-10 minutes each; the harness caps each at 10 minutes. Laptop sleep or VPN loss during a run leaves a hung JVM: kill the surefire fork if that happens.
